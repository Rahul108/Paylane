# Paylane Platform: Agent Guide (`agents.md`)

Master entry point for any agentic coding session in the Paylane platform.

## 1. Project Summary

**Paylane** (each payment journey runs in its own lane) is a local-only payment platform modeling end-to-end real-world payment flows without real money or real external payment gateways.
- Multi-service architecture built with Go 1.22+ and Next.js (TypeScript).
- Zero shared domain code, database-per-service (MySQL 8.0), and signed-then-encrypted service-to-service communication (**JWE/JWS** via `go-jose/v4`).
- Mock PGWs (MFS & Card) simulating real hosted checkout pages, OTPs, webhooks, callbacks, timeouts, and failures.
- Interactive Web Test Console to trigger every scenario, inspect ledger entries, transitions, and run reconciliations.

## 5. Non-Negotiable Architectural Rules

1. **Real microservices, no monorepo coupling**: Every service is independent with its own `go.mod`, Dockerfile, migrations, tests, and README. No `go.work`, no cross-service Go imports. Network-only communication.
2. **Database per service**: Each service owns its dedicated MySQL database and DB user. Cross-database queries are forbidden.
3. **No shared domain code**: HTTP API (OpenAPI) is the contract. Only `paylane-jwe` infrastructure library is shared.
4. **Money is `int64` minor units** (poisha/cents) + 3-letter currency code (e.g. `BDT`). Never floating-point.
5. **Application-generated ULIDs**: Keys are generated by application code, not database auto-increments.
6. **payment-core is source of truth**: Only `payment-core` decides payment state transitions. Orchestrator and web react.
7. **Orchestrator has no payment rules**: It manages step sequences and records attempt progress.
8. **Fail loudly**: Invalid state transitions, expired/tampered JWE tokens, and unknown keys fail with explicit errors.
9. **Never log/store secrets**: Full PAN, CVV, OTPs, raw private keys, or raw JWE payloads are never persisted or logged.
10. **Docs are part of code**: Every architectural or behavioral change must update corresponding `docs/` in the same commit.

## 6. How to Run, Test, and Reset

```bash
# Generate dev RSA/EC keys
./scripts/keygen.sh

# Start entire stack locally
docker compose up -d

# View logs
docker compose logs -f

# Run end-to-end scenario verification
./scripts/e2e.sh

# Reset state (wipes databases and re-runs migrations)
./scripts/reset.sh

# Teardown
docker compose down -v
```

## 7. Definition of Done

- `docker compose up -d` starts MySQL, Redis, and all 6 application services with green health checks.
- All inter-service calls use JWE (Sign-then-Encrypt) with valid audience/issuer and replay cache.
- Every scenario in section 10 of the spec can be triggered from the test console.
- Zero cross-service imports; no `go.work`.
- All migrations run automatically on startup via goose.
- Unit and integration tests pass cleanly.
